Ask your data in plain English: what it takes to build it safely

Letting staff ask sales questions in plain English is one of the most useful AI tools I've built. The setup, the guardrails, and the test it has to pass first.

October 8, 2026

Every business has someone who becomes the human search engine for numbers. "What did we sell last Tuesday?" "Which locations are behind this month?" Each question is quick. Together, they eat that person's week.

So I built a tool where staff type the question in plain English and get a table or a chart back, without waiting on anyone. It reaches more people than anything else I've built, and it's the one I was most careful with.

How it works

  • A person types a question the way they'd ask a coworker.
  • An AI model turns it into a database query.
  • A safety filter checks that query before it runs.
  • It runs through a view-only account that can read data but can't change anything.
  • The answer comes back as a table or a chart.

The guardrails

Read-only, always. The AI never gets an account that can write to the real database. If something goes wrong, the worst case is a bad answer, never damaged data.

Show your work. Every answer has a "check how I got this" panel that shows exactly what was asked of the database. People trust numbers more when they can see the recipe, and they catch mistakes faster too.

Let plain code do the math that matters. Where the arithmetic is fixed, like turning recipes into supply needs, regular code does the math and the AI only interprets the question. AI is great at understanding what you mean. Plain code is better at multiplying.

Sign-in first. The tool sits behind company sign-in plus a list of who's allowed to use it.

The test it has to pass

Before every release, there's a set of test questions with known right answers. The current version got all 36 right before it went live, and a new version doesn't ship if it misses any.

After launch, I also audited the real questions people asked, not just my test set. Real people phrase things in ways you'd never predict, and that's where you find the gaps.

Is this right for your business?

It's a bigger build than most AI projects: think 6 to 10 weeks, not days. It's worth it when:

  • Your data already lives in a system you trust, like a database or a solid reporting tool.
  • Several people ask number questions every week.
  • Someone is clearly the bottleneck for answers.

If your data lives in scattered spreadsheets, start by getting it into one place. That's not glamorous, but every AI tool built on messy data inherits the mess.
